# plan.json —— 计划层表示（八层）

> **为什么要有这一层**：现行工作流是「写音符 → 看统计指标」。而统计指标在音符层面**没有梯度**
> ——把一个旋律音在 ±7 半音内遍历 15 个候选，总分一分不动（四拍恒 8.0 / 余温恒 9.0 /
> 未寄出的信恒 10.0）。零梯度 + 双值禁令 = 只能做约束满足，而**能局部满足的禁令必然被局部满足**，
> 叠加起来就是"什么都不违反、也什么都不说"。
>
> 计划层换掉的对象不是"规则多少"，而是**检查发生在哪一层**：把检查放在写音符之前，
> 检查的是"每个层级的决定有没有做"，而不是"每个音符合不合规"。

## 用法

```bash
# 1) 先写计划，只查计划本身（不写一个音符就能查）
python toolkits/aria-midi/plan_check.py --plan <歌名>/plan.json

# 2) 写完音符，再查音符有没有把计划做出来
python toolkits/aria-midi/plan_check.py --plan <歌名>/plan.json --song <歌名>/song.json

# 3) 给旧作补计划（或学习结构）：从成品反推草稿
python toolkits/aria-midi/plan_check.py --derive <歌名>/song.json \
       --chords <歌名>/chords.json --out <歌名>/plan.json
```

## 八层字段

| 层 | 字段 | 必填 | 说明 |
|----|------|------|------|
| 1 曲式 | `form[]` | ✅ | `{label, bars:[起,止], function}`；function 用 establish / develop / contrast / climax / release |
| 2 调性 | `key`, `harmony[]`, `cadences[]` | ✅ | `key:{root,mode}`；`harmony:[{bar, chords:[[名,型,拍],…]}]` 逐小节；`cadences:[{bar,type}]` 每段末一个 |
| 3 音区 | `voices[]` | ✅ | `{name, band:[低,高], role}`。多声部时**相邻声部间隔 ≥7 半音** |
| 4 织体 | `texture[]` | ✅ | `{bars, figure, density}`。≥2 种织体且密度随段落变化 |
| 5 乐句 | `phrases[]` | ✅ | `{bars, start, goal, breath, cadence}` —— **四列**：起音 / 目标音 / 呼吸点 / 终止音 |
| 6 骨架 | `climax` | ✅ | `{bar, note}` 全曲最高音及其位置 |
| 7 能量 | `energy[]` | ✅ | `{bars, level}` 逐段强度，不能是常数 |
| 8 动机 | `motif` | ✅ | `{degrees:[级数…], appearances:[{bar, op}]}`，op ∈ state / transpose / invert / retrograde / augment / truncate / head_keep_tail_change / cadence_change |

顶层还有 `name` / `bpm` / `meter` / `window_beats`（默认 4，即 4/4 的一小节）。

`breath` 写成 `"小节:拍"`（如 `"4:2"` = 第 4 小节第 2 拍）；`--derive` 生成的记的是**空当之后那个音的起点**。

## 门 / 提示的划分（这是本层的核心设计）

**门（不通过就不该往下写音符）**——只查"结构件在不在、自不自洽"：

| 门 | 判什么 |
|---|---|
| 曲式：≥2 段且每段有 label 与 function | 有没有分段，而不是一味平铺 |
| 和声：逐小节声明了进行 | 和声是骨架，不能省 |
| 和声：每段末尾标注了终止式 | 段落有没有"句号" |
| 音区：多声部时间隔 ≥7 半音 | 会不会糊成一团 |
| 织体：≥2 种织体且密度随段落变化 | 织体有没有参与结构 |
| 乐句：每句都有起音 / 目标音 / 终止音 | **目标音是梯度的来源**——没有目标就只能约束满足 |
| 乐句：≥1/3 的乐句声明了呼吸点 | 有没有换气这件事 |
| 骨架：声明了全曲最高音及其小节 | 高点是不是被决定过 |
| 能量：曲线不是常数 | 至少有一条曲线在动 |
| 动机：≥2 次出现、含 ≥1 次非原样陈述 | 有没有"回来" |
| 自洽：乐句都落在某段之内 | 段落与乐句不打架 |

**提示（只报不判）**——以下每一条都**被 Wait Day 或真实作品纠正过**，它们是风格选择，不是缺陷：

| 提示 | 为什么不能当门 |
|---|---|
| 段落长度非 4 的倍数 | Wait Day 全曲 6×4，属合法写法 |
| 终止音逐句交替（问答感） | Wait Day 的 4 小节级全落 C5，问答发生在 2 小节级 |
| 末句落主音 | POP909 300 首真人旋律里只有 **29%** 落主音（关系调主音也算 57%）——43% 在中音/下属音/下中音收束。这是风格选择，不是通例 |
| 最高音落在 35%~90%（拱形） | Wait Day 的 A5 在 29%——早现的单一高点也是合法写法 |
| 多声部音区间隔 | 反推计划得到的是实测 min/max（含一次性填充音），不是声明的"工作带" |
| 单声部 / 单织体 | 纯旋律草图天然只有 1 个 |

## 效度检验（把每道门放到真实人写语料上跑）

纪律：**任何指标在进门之前，先在真人作品上量误杀率。** 300 首 POP909 旋律实测：

| 门 | 误杀率 |
|---|---|
| 曲式 / 乐句三列 / 呼吸点 / 骨架 / 能量 / 动机 / 自洽 | **0%** |
| 和声两项 | 不适用（POP909 无和弦文件；已区分为"未评估"而非"不通过"） |

这一轮检验打回了三处，都是我的错，不是真作品的错：

1. **末句落主音 70.7% 误杀** → 降为提示。实测 300 首里只有 29.3% 落主音，
   接受关系调主音后 57.3%，其余在中音(19%)/下属音(14%)/下中音(13%)收束。
   项目文档原话"全曲最后一音必须是主音长音"是古典/民谣惯例，**不是流行旋律的通例**。
2. **和声两项 100% "误杀"** → 是输入缺失的假象（语料没有和弦文件），
   已区分"源文件未提供和弦数据 → 未评估"与"计划漏写和声 → 不通过"。
3. **能量曲线常数 6.3%** → 根因是我的能量代理用了力度，而 POP909 的力度常被导出拉平
   ——**量到的是导出方式不是音乐**（第三次踩同一个坑）。已改用密度。

顺带发现的已知弱点：`--derive` 的调性推断用"最多音落在音阶内"，**无法区分关系大小调**
（C 大调与 A 自然小调音集相同），实测在偏大调的华语流行上把 192/300 判成小调。
所以凡与"主音"有关的判断都只作提示，不作判定。

> ⚠️ 这份 0% 有同义反复的成分：反推的计划天然是完整的，所以它只证明"门不误杀真作品"，
> 不证明"门能抓出坏作品"。**门的牙齿要用独立写下的计划才显出来**——见下节交叉测试。

## 反向验收（本层的验收标准）

**计划检查器必须能对已知好作品判"通过"。** 实测（`--derive` 反推 + 检查）：

| 作品 | 计划层计分 | 不通过的门 |
|---|---|---|
| Wait Day（人写·反推计划） | **9/9** | 无 |
| 晚归（人写·**手写计划**+实现） | **11/11** + 实现 6/6 | 无 |
| 四拍（机写） | 8/9 | 乐句：≥1/3 的乐句声明了呼吸点（0/2） |
| 霓虹夜行（机写） | 10/10 | 无 |

**注意霓虹夜行这一行**：它的计划层能通过，因为它的缺陷不是"计划缺件"而是"实现走偏"
（碎片化、大跳成串）——反推的计划如实描述了它，所以自洽。这类问题由另一张网抓：
`analyze --baseline` 显示它的 `breaths_per_beat` 高于 p95、`step_share` 低于 p05。

**三层分工**：

| 层 | 抓什么 | 抓不到什么 |
|---|---|---|
| `plan_check`（计划层） | 某个层级**没有做决定** | 决定做得不好 |
| `analyze --baseline` | 实现走偏到统计极端 | 平庸但不极端 |
| **耳朵** | 好不好听 | —— |

实现层的牙齿要用**独立的计划**才显出来：拿 Wait Day 的计划去对四拍的音符，
得 3/6——目标音缺失、呼吸点不到位、动机不匹配。用 `--derive` 反推的计划自查则必然通过
（它本来就是从那些音符抄的）。
