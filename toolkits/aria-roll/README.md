# aria-roll — 零依赖钢琴卷帘渲染器

Aria 技能包子工具（v1.0.0）：把 `song.json` 或**任意 `.mid`** 渲染成**自包含 HTML 卷帘** —— 双击就看（Canvas 卷帘 + 时间游标），按播放就听（Web Audio 现场合成，**不需要 DAW、不需要插件、不需要音源**）。也可输出静态 SVG。

```
python <本包目录>/toolkits/aria-roll/aria_roll.py roll --input song.json
# 或把 bin 加入 PATH 后直接：
aria-roll roll --input song.json
```

## 为什么需要它

**MIDI 是谱，不是声音。** Aria 整条管线都是符号化的（`song.json` → `.mid`），从头到尾没有任何一步变得可听可看。结果是：人拿到产物只能拉进 DAW、启插件、再导入 —— 一个纯属多余的往返，而且**回程是断路**（改完带回来的不是 `song.json`，不能 validate / analyze / 重生成）。

本工具消掉这个往返：产物是**一个 HTML 文件**，无外部依赖、无构建步骤、双击即用。声音在浏览器里实时合成，所以文件里**不塞音频**（100 秒 WAV 好几 MB，base64 还要再涨三分之一），只传谱 + 一个合成器。

## 定位规则

依赖同级的 `aria-decode`（仅在输入 `.mid` 时需要）。向上查找 `skills/` 不需要 —— 本工具不读知识库。

## 用法

```
aria-roll roll --input <song.json 或 x.mid> [--output <路径>] [--format html|svg]
               [--title <标题>] [--zoom <像素/拍>]
```

| 选项 | 说明 |
|------|------|
| `--input` | `song.json` 或 `.mid`（自动识别后缀，`.mid` 走 aria-decode）；`-` 读 stdin JSON |
| `--output` | 输出路径。省略时按**歌名派生** `<输入目录>/<歌名>.html`（或 `.svg`）；`-` 写 stdout |
| `--format` | `html`（默认，自包含可播放）/ `svg`（静态，适合 Agent 读图或嵌文档） |
| `--title` | 覆盖标题（默认取 song.json 顶层 `name`，`.mid` 取文件名主干） |
| `--zoom` | HTML 初始像素/拍（6–90，默认 16）。页面会先**自适应铺满可视宽度**，低于 5 px/拍才改为横向滚动 |

**退出码**：`0` 成功 / `1` 数据错误（JSON 解析失败、无音符）/ `2` 用法错误（缺参数、文件不存在、输出目录不可写）。

### 示例

```bash
# 作曲产物 —— 派生到歌曲目录，与 song.json / .mid 并列
aria-roll roll --input 未寄出的信/song.json
#   → 未寄出的信/未寄出的信.html

# 拿到别人的 MIDI，先看它长什么样（不需要任何 DAW）
aria-roll roll --input "Wait Day.mid"

# 静态卷帘，给可读图的 Agent 或嵌进文档
aria-roll roll --input song.json --format svg

# 管道
cat song.json | aria-roll roll --input - --output - > roll.html
```

## HTML 里有什么

- **Canvas 卷帘**：按半音一行，左侧是带 `C4` 标注的琴键条，黑键行有底色便于定位；纵向拍线 / 小节线（按拍号）并标小节号
- **按轨配色**：轨道依序取调色板；**GM 打击乐通道（channel 9）固定用中性灰**，一眼能和旋律区分
- **力度映射透明度**：越响越实（0.45–1.0）
- **播放**：Web Audio 现场合成，音色按 GM program 分族（钢琴 / 铃 / 风琴 / 吉他 / 贝斯 / 弦乐 / 簧管 / 主音 / 铺底 / 拨弦；打击乐用噪声+滤波）；播放头跟随并自动横向滚动
- **图例可独奏**：点某轨只看/只听它，再点取消
- **快捷键**：空格播放 / 停止
- **循环播放**开关、缩放滑块
- **诊断钩子** `window.__aria()`：在控制台确认音频上下文状态、已排程节点数、播放头位置 —— 排「为什么没声音」时有用

## 输出格式与体积

音符以内嵌 **整数四元组** `[pitch, start×4, dur×4, velocity]` 传递（网格是 0.25 拍，×4 必为整数），比带键名的对象小约 3/4：

| 输入 | 音符数 | HTML | SVG |
|------|-------|------|-----|
| 3 轨钢琴曲 | 658 | ~21 KB | ~43 KB |
| 5 轨 EDM（含鼓） | 2142 | ~42 KB | ~90 KB |
| 人类编曲单轨 MIDI | 398 | ~17 KB | — |

## 已知限制

- **音质有天花板。** Web Audio 振荡器 ≠ 真钢琴。判断结构、和声、旋律、节奏完全够用，要出版级音色还是得回 DAW 挂音源。
- **Agent 听不见。** 生成音频只对人类有用；对 Agent 而言只有 `--format svg`（或文本化的音符数据）算「看得见」。别指望它改善 Agent 的反馈回路。
- **浏览器自动播放策略。** 首次点击播放时若 AudioContext 被挂起，页面会提示「静音预览」。此时**播放头照常走**（视觉时钟用 `performance.now()`，与音频时钟解耦），再点一次播放通常即可出声。
- **超大作品滚动偏多。** 自适应有 5 px/拍下限，超过就横向滚动。2000 音符以上的曲子建议用缩放滑块或 `--zoom` 调。
- **编辑尚未实现。** 当前是只读预览（看 + 听）。「在页面里改音符并导出 `song.json`」是下一步，会引入「谁是权威版本」的问题，需要配套的 diff / 回程格式设计。
- **HTML 依赖浏览器。** 无 JS 环境下只能看 `--format svg`。

## 浏览器实测记录

本轮开发中在真实浏览器（Chromium / IAB）里实测过，并有截图确认渲染。过程中发现并修掉两个真 bug：

1. **小节数 off-by-one** —— `int(total // bpb) + 1` 把 128 拍算成 33 小节（应为 32）。已改为向上取整。
2. **播放头卡死且为负数** —— `AudioContext` 被自动播放策略挂起时 `currentTime` 冻结，而代码立刻用它算起点，`resume()` 的 Promise 也没等。已改为视觉时钟与音频时钟解耦。

另外 `fitWidth()` 最初把判断写反了（「放不下就返回」，导致从不自适应），已修正为默认铺满、用户动过缩放后不再自动改。
